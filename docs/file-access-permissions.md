# Доступ к папке результатов (File System Access API)

Почему popup иногда пишет «Не сохранено на диск», когда изменения попадают в папку и откуда можно запрашивать разрешение.

## Главное: доступ нужно просить по клику на странице расширения

Проверено в Яндекс Браузере 18.10.2026:

- Доступ на запись живёт, пока открыта вкладка расширения, на которой его получили (и другие вкладки расширения). Когда закрывается последняя, доступ пропадает. Из документации Chrome: «Access lasts until you close the last tab of the origin».
- Сам по себе доступ не возвращается: на свежеоткрытой странице `queryPermission()` даёт `prompt`, даже если раньше выбрали «Разрешать всегда».
- «Разрешать всегда» (*Allow on every visit*) убирает только вопрос. Следующий `requestPermission()` проходит молча, без окна, но вызывать его всё равно нужно и только в ответ на действие пользователя (клик).
- Popup и фоновый service worker вкладками не считаются. Без открытой страницы расширения с полученным доступом фоновое автосохранение на диск не пишет.

## Как расширение с этим живёт

- **Что уже на диске.** `lib/folder.js` хранит в `chrome.storage.local` ключ `folderSynced` вида `{ [reviewId]: updatedAt }` — какая версия каждого ревью записана на диск. `unsavedReviews()` возвращает ревью, чья текущая версия новее записанной.
- **Дописывание.**
  - `flushUnsaved()` без запроса пишет несохранённые ревью, если доступ уже есть.
  - Страницы ревью и отчёта зовут `flushUnsaved()` при открытии. Если доступа нет, `regainAccessOnClick()` просит его при первом клике на странице: с «Разрешать всегда» браузер отдаёт его молча. После этого несохранённое дописывается.
  - Фоновый `syncReview()` после успешной записи тоже дописывает накопившееся.
- **Popup.** Если доступа нет (страница ревью закрыта), popup показывает «Нужно разрешение на запись в «uniform-reviews-results»: запросить» и число несохранённых ревью. По клику открывается страница ревью: первый клик на ней возвращает доступ, а пока она открыта, ревью сохраняются. Если доступ есть, но что-то не дописано, popup показывает «Не сохранено…: сохранить» и дописывает сам.
- **Восстановление.** Ревью, восстановленные из папки, уже лежат на диске, поэтому `importFromFolder()` сразу помечает их записанными.

## Откуда запрашивать разрешение

- **Только со страницы расширения по клику:** кнопка на `setup.html?grant=1`, «Разрешить доступ» в блоке папки на `review.html`.
- **Не из popup.** `requestPermission()` из popup запрос не показывает, вызов фактически зависает.
- **Не из фонового скрипта:** там можно только проверить доступ (`folder.permission(dir)`).
- Вариант «Разрешать всегда» браузер предлагает только при повторном `requestPermission()` на дескрипторе, сохранённом в IndexedDB. Сразу при выборе папки его нет.

## Восстановление ревью

По кнопке «Восстановить ревью из папки» папка открывается только для чтения (`pickResultsFolder({ readOnly: true })`), и браузер не спрашивает про запись. Запись понадобится, когда появятся несохранённые изменения. Тогда popup покажет «сохранить».

## Источник

[Persistent permissions for the File System Access API](https://developer.chrome.com/blog/persistent-permissions-for-the-file-system-access-api) — блог Chrome for Developers.

## Разрешение «навсегда» расширению не дают

Проверено 18.10.2026: Яндекс Браузер не предлагает расширению «Allow on every visit» для записи. После каждого закрытия страниц расширения он снова показывает обычный запрос «Save changes to uniform-reviews-results?».

Поэтому popup и блок папки на странице ревью просят держать страницу ревью открытой во время работы.

Пробовали сохранять копию в `~/Downloads/uniform-reviews-results/` через `chrome.downloads` и offscreen-документ, без разрешений на папку. Копия работала, но её убрали по решению владельца продукта.
